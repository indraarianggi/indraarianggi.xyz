# Indra Arianggi: Portfolio

Personal portfolio built as a static Astro site in a Swiss Poster + Analog Notebook visual system. Work, articles, and books are authored as Markdown, validated by type-safe content collections, and rendered into static HTML with no client framework.

Headline: "Making software. Learning as I go."

## Stack

| Concern | Choice |
|---|---|
| Framework | Astro 7 (`output: 'static'`) |
| Language | TypeScript, `astro/tsconfigs/strict` |
| Content | Markdown via Astro content collections (`glob` loader, Zod schemas) |
| Styling | Native CSS with custom properties in `src/styles/global.css` |
| Type | Archivo Black, Archivo, Literata, IBM Plex Mono (local Fontsource packages) |
| Icons | `astro-icon` with `@iconify-json/ph` |
| Feeds | `@astrojs/rss`, `@astrojs/sitemap` |
| Navigation | Astro `ClientRouter` plus one vanilla script for the table of contents |
| Tests | Vitest |
| Package manager | pnpm 11 |

Astro 7 requires Node `>=22.12.0`. The pinned package manager is `pnpm@11.20.0`.

## Getting started

```bash
pnpm install
pnpm dev          # dev server on http://localhost:4321
```

| Script | Command | Purpose |
|---|---|---|
| `pnpm dev` | `astro dev` | Local dev server with hot reload |
| `pnpm check` | `astro check` | Type and template diagnostics |
| `pnpm test` | `vitest run` | Unit tests for content and TOC helpers |
| `pnpm test:watch` | `vitest` | Watch mode |
| `pnpm build` | `pnpm check && astro build` | Type-check, then generate `dist/` |
| `pnpm preview` | `astro preview` | Serve the built output |

`pnpm-workspace.yaml` grants the `esbuild` build script the approval pnpm 11 requires.

## Environment

`SITE_URL` sets the canonical origin used by canonical links, Open Graph URLs, `sitemap-index.xml`, `robots.txt`, and the RSS feed. `.env.example` records the variable name.

```bash
SITE_URL=https://your-production-domain.example pnpm build
```

When `SITE_URL` is unset, the site falls back to `http://localhost:4321`.

`astro.config.mjs` reads `process.env.SITE_URL`, so the value must be exported in the shell or set by the CI environment. Astro loads `.env` files into `import.meta.env` through Vite and does not populate `process.env` before evaluating the config, so a `.env` file alone does not change the canonical origin. Verified by building with only `.env` present: canonical URLs stayed at `http://localhost:4321`.

## Routes

| Route | Surface |
|---|---|
| `/` | Poster hero, selected work (up to 3 featured), recent writing (up to 4), reading desk (1 current, 2 finished) |
| `/work/` | Work index: numbered rows paired with a feature stage |
| `/work/<id>/` | Project detail: status/role/stack metadata field, prose, contents rail |
| `/blog/` | Field notes: latest article lead plus a ruled archive |
| `/blog/<id>/` | Article detail: published/topics metadata field, prose, contents rail |
| `/about/` | Learning poster and practice statement with analog notes |
| `/read/` | Book shelves, grouped by reading state |
| `/404` | Misprint poster with direct recovery links |
| `/rss.xml` | Blog feed, empty but valid when no articles are published |
| `/robots.txt` | Crawl policy pointing at the sitemap |
| `/sitemap-index.xml` | Generated by `@astrojs/sitemap` |

Detail routes render the contents rail only when the document has at least two `h2` sections. Collapsing the desktop rail does not change the reading measure.

## Writing content

Add a Markdown file to the matching collection folder. The file path minus the `.md` extension becomes the URL id, so `src/content/work/example-project.md` is published at `/work/example-project/`. Files whose name starts with `_` are ignored by the loader pattern.

Drafts (`draft: true`) render in `astro dev` and are excluded from `pnpm build` output and from the production detail routes.

Collections are ordered by `date` descending. Books are then grouped in the order reading, finished, paused, want to read; within a group, entries sort by ascending `order`, and entries without `order` come last. Paused and want to read share one visual shelf while each entry keeps its own status label.

### `work`

```yaml
---
title: Example project
summary: One line describing what the project is and why it exists.
role: Design and implementation
status: building        # building | shipped | paused | archived
date: 2026-09-01
endDate: 2026-11-30     # optional
stack: [TypeScript, Astro]
repository: https://example.com/repo   # optional
website: https://example.com           # optional
featured: true          # optional, surfaces on the homepage
draft: false            # optional
image: ./cover.png      # optional, colocated in this folder
imageAlt: Diagram of the project pipeline  # required when image is set
---
```

### `blog`

```yaml
---
title: Example note
description: One line summary used in listings, feeds, and metadata.
date: 2026-09-14
updatedDate: 2026-09-20   # optional
topics: [astro, css]
draft: false              # optional
image: ./header.png       # optional
imageAlt: Screenshot of the rendered archive  # required when image is set
---
```

### `books`

```yaml
---
title: Example book
author: Example Author
status: reading           # reading | finished | paused | want-to-read
date: 2026-09-01
startedDate: 2026-09-01   # optional
finishedDate: 2026-09-14  # optional
order: 1                  # optional, editorial order within the shelf
draft: false              # optional
cover: ./cover.png        # optional
coverAlt: Cover of Example book  # required when cover is set
---
```

Images are processed by the Astro image pipeline and must live beside the entry that references them. Set `imageAlt` (or `coverAlt` for books) whenever an image is present; the schema rejects entries that omit it.

## Design system

Tokens live in `src/styles/global.css` and match `DESIGN_REPORT.md`.

| Token | Value | Use |
|---|---|---|
| `--paper` | `#f1efe8` | Page background |
| `--surface` | `#fffdf8` | Raised paper fields, text on ink |
| `--ink` | `#0a0a0a` | Body text, ink fields |
| `--ink-on-red` | `#000000` | Normal-size text on signal-red fields |
| `--muted` | `#6b6861` | Secondary metadata |
| `--rule` | `#b9b4aa` | Structural rules and borders |
| `--red` | `#e33122` | Signal red: fields, rules, decorations, qualifying large text |
| `--red-soft` | `#f5d8d2` | Active contents background |
| `--focus-ring` | `#e33122` | Focus outline |

Type roles: Archivo Black (`--font-poster`) for poster headlines, Archivo (`--font-sans`) for interface text, Literata (`--font-serif`) for prose, IBM Plex Mono (`--font-mono`) for metadata and field-note labels.

Content and design invariants:

- Light theme only, with one signal-red accent.
- Primary navigation is Home, Work, Blog. About and Read appear on the homepage and in the footer only.
- No gradients, glass effects, heavy shadows, decorative dots, or rounded card grids.
- Hover effects are gated behind `(hover: hover) and (pointer: fine)`; spatial animation has a reduced-motion alternative.
- Empty collections must render an intentional empty state, never a broken layout.
- No visible em dash characters in page copy.
- Do not invent projects, employment history, metrics, articles, books, or contact details. `src/config/site.ts` keeps `socialLinks` empty until real destinations exist.

To use additional icons, add them to the `include` map for `ph` in `astro.config.mjs`; only `list-bold` and `x-bold` are bundled today.

## Verification

```bash
pnpm test     # 11 tests covering src/lib/content.ts and src/lib/toc.ts
pnpm check    # 0 errors, 0 warnings, 0 hints
pnpm build    # type-check plus static build of every route
```

`pnpm check` and the build emit empty-collection notices while `src/content/work`, `src/content/blog`, and `src/content/books` contain no published Markdown. Those notices disappear once real entries exist.

The current build was verified in a production preview at 1440px and 390px: Lighthouse accessibility, best practices, and SEO scored 100 on every route, with zero console errors, failed assets, or horizontal overflow. Accessibility details worth preserving during edits:

- Normal-size red text fails WCAG AA on both paper (3.85:1) and ink (4.45:1), so small labels use `--ink` on light surfaces, `--surface` on ink fields, and `--ink-on-red` on red fields. Red remains for fields, rules, decorations, and qualifying large text.
- The mobile masthead keeps the full name "Indra Arianggi" in the accessibility tree while showing the `IA` mark visually.
- The skip link targets `#main-content`, and `prefers-reduced-motion` disables smooth scrolling and animations.

## Deployment

`pnpm build` writes a static site to `dist/`. Deploy that directory to any static host and set `SITE_URL` to the real origin so canonical URLs, the sitemap, `robots.txt`, and the feed are correct.
